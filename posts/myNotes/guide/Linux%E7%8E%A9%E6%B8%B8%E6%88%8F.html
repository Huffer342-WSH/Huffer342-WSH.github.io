在 Linux 下直接运行 Windows 分区中的游戏

2026-06-04
1.1k
6m
教程

我的电脑采用的是 Windows + Linux 双系统。平时的工作、学习都在 Linux 下完成，而游戏则全部安装在 Windows 系统的 NTFS 分区中。

由于我不想为了清日常（原神、终末地）专门重启进入 Windows，因此希望直接在 Linux 中运行已经安装在 NTFS 分区里的 Windows 游戏。

在 Linux 上运行 Windows 游戏一般是通过 Proton 实现的。在 V 社的推动下，如今大部分游戏都可以在 Linux 下运行，同时也出现了许多易于使用的管理工具，不像几年前直接使用 Wine 那样折腾。

Linux 下常见的 Proton/Wine 管理工具 ​

除了 Steam 之外，目前 Linux 社区常见的几个游戏启动器包括：

  • Faugus Launcher
  • Lutris
  • Bottles
  • Heroic Games Launcher

它们本质上都是帮助用户管理 Wine Prefix、Proton 版本以及游戏启动参数的工具。

经过一段时间尝试后，我最终选择了 Faugus Launcher。

为什么选择 Faugus Launcher ​

原因很简单：Faugus 能用，而且足够轻量。

从应用快捷方式启动游戏时不会弹出额外窗口，也不会先启动 Faugus 本体；同时还能自动从 Steam 中搜索可用的 Proton 版本。

接下来我将一一批斗其他管理器。

其他方案的问题 ​

Steam ​

Steam 本身当然可以通过“添加非 Steam 游戏”的方式运行。

但是如果我只是想打开一个游戏，还得先启动 Steam，而 Steam 的启动速度又比较慢。

另外，Steam 无法自定义 Wine Prefix 的位置，并且每个应用都会单独创建一个 Prefix，比较浪费磁盘空间。

Lutris ​

无法运行原神

也许可以通过修改配置运行，但是不够轮椅，Out。

Heroic Games Launcher ​

Heroic 最大的卖点是整合了Epic Games、GOG之类的，但是用不上。而且在运行游戏时会打开 Heroic 本体，即使勾选了“不打开界面”，启动时依然会闪一下窗口。

Bottles ​

Flatpak 安装包太大，懒得安装，直接 Out。

具体配置 ​

Proton 选择 ​

国内二游选择 DW-Proton

对于Faugus来说安装到~/.local/share/Steam/compatibilitytools.d/路径下就行，和steam共享。所以也可以使用 ProtonPlus 给 Steam 安装 DW-Proton

1.21.1版本后Faugus内就能安装

NTFS 分区开机挂载 ​

由于游戏安装在 Windows 分区，因此需要保证 Linux 能正确挂载 NTFS。

我的配置如下：

fstab
## /dev/nvme0n1p3
UUID=62B2944DB2942795 /media/appdisk ntfs3 force,nofail,uid=1000,gid=1000,rw,user,exec,umask=000 0 0

使用 ntfs3 驱动挂载，性能会稍微好一些。

不过 ntfs3 经常会因为分区处于 dirty 状态（通常是 Windows 干的）而导致挂载失败，所以建议加上 nofail，防止开机时进入紧急模式（Emergency Mode）。

如果已经确保windows那边不会起冲突，可以加上force。

如果挂载失败，先检查是不是dirty的问题：

sh
~
❯ sudo dmesg | grep  ntfs
[    8.440961] ntfs3: Enabled Linux POSIX ACLs support
[    8.440964] ntfs3: Read-only LZX/Xpress compression included
[    8.449709] ntfs3(nvme0n1p3): It is recommended to use chkdsk.
[    8.466221] ntfs3(nvme0n1p3): volume is dirty and "force" flag is not set!

是的话可以使用以下命令修复（记得替换成自己的分区）：

sh
sudo ntfsfix -d /dev/nvme1n1p3

然后重新挂载：

sh
sudo mount -a

Wine Prefix 规划 ​

在 Linux 或 macOS 上使用 Wine 运行 Windows 软件时，Wine 需要模拟出一个完整的 Windows 环境，这个模拟出来的独立运行环境就叫做 WINEPREFIX。

很多启动器默认会为每个应用单独创建一个 Wine Prefix。

不过经过我的实际测试，原神和终末地可以共用一个 Prefix，目前没有遇到任何兼容性问题。
